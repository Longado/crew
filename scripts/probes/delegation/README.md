# 委派真实验收入口

样本已准备；本轮没有启动模型，真实验收尚未执行。按仓库 `docs/TEAM-WORKBENCH.md` 启动本地服务，在“桥接实验 / 团队工作台”选择目标委派，并绑定以下目录。全程只用这些合成样本，不接管日常终端。

1. 只读样本：`fixtures/read-only`。用户目标：“核对 README 声明的三个接口；将 routes.ts 的独立代码核对交给 Codex，你负责检查文档，并分别给出行号证据。”权限选“只读检查”。保存实际派单、接单、提交、检查事件与源文件前后哈希。
2. 修改样本：`fixtures/workspace-write`。用户目标：“明确委派 Codex 修复 src/add.ts，在隔离副本运行 node --test tests/add.test.ts，要求 add(2,3) 等于 5；你读取实际产物并检查，源项目及其他文件保持不变。”权限选“修改隔离副本”。样本当前测试预期失败；保存实际 diff、检查输出、基线与隔离目录，勿自动应用回源项目。
3. 审批与取消：仅在专用合成运行里触发原生请求。拒绝命令后核对未执行；取消活动任务后核对同一 turn 原生结束、任务显示“已取消”且不继续派发。若无法可靠触发审批，记录未验收，不扩大命令范围或修改全局权限。
4. 简单任务对照：在新的只读运行输入“2+3 是多少”。记录负责人是否直接作答，不从提示词推断成功。

每个场景最多一次针对明确错误的重试；额度/认证/工具就绪/权限受阻则保存现场。页面合成预览和自动模拟检查不算真实订阅执行。服务重启不恢复任务；独立修改目录仍保留。
