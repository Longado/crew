# Crew 终端团队入口

从仓库目录执行。当前入口是独立 TUI，复用网页团队的工作逻辑，创建本次专用会话；没有接管已有 Codex、Claude 或网页会话。Codex 模式使用 [App Server stdio](https://learn.chatgpt.com/docs/app-server)，不需要网页服务器或 TCP 监听。

## 先查看界面（离线）

```sh
npm run crew -- team --demo
```

标题明确显示演示。成员、提问、审批和记录来自离线样本，不检查订阅、不调用模型、不执行样例命令；进度不虚构验收。Tab 切换成员，输入 `/answer Q1` 回答格式问题，再输入 `/approve A1 n` 拒绝样例审批。F2 查看详情；`/interrupt` 请求中断所选成员；`/quit` 停止并退出。

## 真实只读团队

在正常桌面终端执行：

```sh
npm run crew -- team scripts/probes/delegation/fixtures/read-only
```

先看到只读状态，输入一个固定目标：

> 仅检查 README.md 和 src/routes.ts。请让两位成员分别读取两个文件，记录各自职责与验收条件，汇总文件内容、发现的问题和来源位置。不要修改文件、安装依赖或联网搜索；检查后等待，不扩大目标。

也可用 `--goal "目标"` 立即开始。项目目录可省略，使用当前目录。默认只读；需要修改时显式加 `--write`，修改与基线保留在隔离副本，不自动合并。跨工具委派可选择 `--mode delegation`，其 Claude 启动命令在主区域显示，需在另一个终端按原生提示连接。

## 操作检查

- 看到真实成员及任务，Tab 切换；普通输入发送给所选原生成员，跨工具模式发送给 Claude 负责人。切换后各成员草稿应保留。
- 看到 Q 编号后使用 `/answer Q1` 逐项填写。选项可以输入数字；私密输入显示星号。`/cancel` 取消填写，原请求仍待回答。
- 审批按 A 编号处理：`/approve A1 y` 允许本次、`n` 拒绝本次、`c` 拒绝并中断；同一请求不重复决定，旧运行编号不能批准新请求。
- `/interrupt` 请求中断所选原生成员；跨工具模式先选择 Codex 执行者。收到原生结束才显示已中断或已取消，保留成果和差异。
- 执行完成与负责人验收分开，底部只计已验收任务。F2 或 `/details` 查看任务职责、成果和变更，PgUp/PgDn 翻阅。
- `/stop` 停止团队并保留本次记录，`/start [目标]` 再启动；`/quit` 或 Ctrl+D 停止本次团队、恢复终端并退出。Ctrl+C 有草稿时清空，没有草稿时请求中断；启动尚未完成时退出。
- 在 100×26 与 42×16 窗口检查中文、emoji、光标和成员条；粘贴中的换行不应自动发送或批准。
