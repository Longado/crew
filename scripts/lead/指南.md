# 负责人模式：Claude Code 拆任务卡，Codex 执行者干活

这份指南由 `crew worker guide` 打印，和命令放在一起改，不会跟功能对不上。
来源：2026-10-08 一次客户材料分析，Claude Code 当负责人、三位 Codex 执行者，出处全部对得上。流程对齐 Orca 编排：一批活一个运行，卡片之间写依赖，结果要明确验收或退回，执行者进程是否还在查得出来。

## 一次运行怎么走

1. 建运行目录，把任务卡放进 `cards/`，一张卡一个 md 文件，文件名就是卡名（如 `t1.md`）。客户材料相关的运行目录放在 `.local-sensitive` 下。
2. `crew worker run <运行目录> --cwd <执行者的工作目录> --goal "<这批要回答什么>"`：所有就绪的卡（没有依赖，或依赖都已验收）同时开跑，**派出去就返回**，不陪着等。每张卡有自己的看守进程盯着，单次最多 30 分钟，超时连同子进程一起关掉。
3. `crew worker wait <运行目录>`：等到有一张卡交回来就返回（先交的先通知），其余的继续跑；再 `wait` 等下一张。没有卡在跑时立刻返回。
4. 逐张验收：先 `crew worker check <运行目录>/t1.out` 把引用对回原文，再挑关键结论读原文，确认原文撑得起结论。然后：
   - `crew worker accept <运行目录> t1 --note "抽查了哪几条"`：有对不上原文的引用时拒绝验收；
   - `crew worker reject <运行目录> t1 --note "哪里不行"`，然后 `run … --retry t1`：**接着原会话改**（`codex exec resume`），执行者带着已读过的材料只处理你写的退回原因，不从头重读；旧结果存进 `history/`。原会话找不到时才整张重派。
5. 再跑一次 `run`：依赖都已验收的卡这时才会开跑，执行者会收到前序交付的路径。
6. `crew worker status <运行目录>` 随时看每张卡在哪一步。全部验收后，负责人自己合成结论，执行者原稿留作附件。

每张卡的回执里有执行者用了多少 token 和会话编号，`status` 也会显示 token。

## 什么活不值得派

每派一个执行者，启动就要花掉约 3 万 token（10-09 三张只读一份短文档的卡，各用了 3.5–3.8 万）。下面这些不要派，自己读：

- 一两个文件、几分钟能读完的活；
- 要边读边改主意、没法事先写清交什么的活；
- 需要执行者中途问你问题的活：执行者不能提问，卡没写清它就自己猜。

适合派的是：要读一大堆材料、能拆成互不依赖的几块、每条结论都要带出处的只读分析。

卡片状态：`ready` 可派，`waiting` 等依赖验收，`running` 在跑，`lost` 进程已不在但没写完回执（结果未知，看日志后退回重派），`delivered` 待验收，`accepted` 已验收，`rejected` 已退回，`failed` 失败，`timed_out` 超时。

## 任务卡怎么写

每张卡要能单独看懂，写清这五样（对应 Orca 的任务说明要求）：

- **读什么**：材料的绝对路径，标明哪些必读、哪些按需。
- **交什么**：几张表，每张表有哪些列，最多几行。
- **口径**：这次特有的说法，例如某个词在这里指什么、哪些数字不能相加、哪些内部讨论不能当报价。
- **边界**：不做什么。
- **怎么算做完**：例如“12 个子项每项一行，每行至少一条出处”。

要用到其他卡的结果时，在卡片第一行写 `依赖：t1, t2`，执行者会拿到前序交付的路径。通用规矩（只读、出处写成 `/绝对路径:行号`、PDF 写 `#p页码`、没出处写“无来源”、区分证据强度）已经自动加在每张卡前面，不用重复写。

拆法：先拆出互不依赖的几项并行派，有依赖的放到后面一波。链条不要超过三四层。

## 要改文件的活：`--write`

有些活必须边改边看：跑 Blender 出图、用无头浏览器截帧、改页面再看效果。Codex 的沙箱挡显卡、挡联网，这类活在只读或写沙箱里都起不来（10-13 实测：Blender 一启动就崩，截帧工具连不上 npm）。`run … --write` 不开沙箱，执行者可以改文件，边界靠两样：

- 每张卡写一行 `可写：seg/a.js, props/a-*`（相对 `--cwd`，可带 `*`；写目录名表示整个目录）。执行者被告知只改这些。
- 第一次 `run --write` 时给工作目录拍一份底（只记每个文件的大小和修改时间）。`crew worker changes <运行目录>` 列出新增、改了、删了的文件，每个归到哪张卡；没有卡认领的算越界，命令返回 1。验收前先跑它。

几条规矩：
- 并行的卡「可写」不要重叠，共享文件（总页面、公共脚本）由负责人派单前改好，或者放进一张卡、其余卡依赖它。
- 一个运行目录要么全只读、要么全 `--write`，`--retry` 也要带同样的旗；`--write` 的运行绑定一个工作目录。
- 改动清单是整批的，分不出哪张卡改的；靠「可写」不重叠来归属。
- 不开沙箱的风险和不开沙箱的 Claude 子 agent 一样，派之前 Eddie 要点过头。

## 边界

- 默认只读；`--write` 见上一节。看板 `crew tasks dispatch --write` 是另一条路：在隔离副本里改，不自动合并。
- 执行者启动前会关掉 Codex 的全部 MCP 和插件，关不掉就不启动。
- 这类运行不进任务库、看板上也看不到；记录都在运行目录里。
- 测试：`python3 scripts/lead/test_worker.py`、`python3 scripts/lead/test_worker_write.py`（用假 Codex，不调用模型）。
