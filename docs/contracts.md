# 约定

代码里的唯一依据是 `src/contracts.ts`，这里只说明设计意图。

## 三层数据

1. **消息**：采集层产出。每条消息的 `id` 用来源自带的稳定编号，重复同步靠它去重。原始时间拿不到就是 `null`，另存采集时间。
2. **证据**：整理层产出，也是全项目唯一用到大模型的地方。一条证据说的是"某几条消息表明某个任务发生了某件事"，必须引用消息编号。
3. **视图**：记忆引擎把全部证据和人工修正按时间折叠出来，包括任务状态、规划版本、决定、待确认、下一步。视图随时可以重算，所以删除一条误归类的记录后，重算一次就好。

## 代码替大模型把的关

- 引用的消息编号必须真实存在，否则丢弃这条证据。
- 说话人由代码从被引用的消息里取。
- "用户确认完成""规划项""规划变更"必须引用至少一条用户消息，否则降级：确认完成降为 AI 自述，规划类降为 AI 建议，进待确认。
- 任务名和已有任务同名时，自动归到已有任务。
- 人工修正优先。修正之后新来的证据如果要改同一个任务的状态，不直接生效，进待确认。

## 状态怎么变

| 证据 | 结果 |
|---|---|
| 规划项、规划新增 | 新任务为待开始 |
| 开始执行 | 进行中（已完成的任务视为重开） |
| AI 称完成 | 待验证，不计完成 |
| 用户确认完成 | 已完成，记一次完成事件 |
| 报告失败 | 进行中（从待验证或已完成重开） |
| 受阻 | 受阻，记下缺什么；已完成的任务也会重开。AI 说的阻塞标为推测 |
| 阻塞解除 | 进行中 |
| 规划取消 | 已取消，退出下一步；取消一个从没进入范围的事项，不建任务，记成否决 |

**来源冲突**：两段不同来源的对话说法相反（一边列进规划或开始做、另一边取消；一边确认完成、另一边报失败），而且两边都拿不到原始时间，就分不出谁在后。这时不按采集先后定，任务保持原状态，进待确认让人定。只有一边拿不到时间的，仍按采集时间排；导入时填上“大约发生在”的日期可以避免。

**消息编辑版本**：改过重发的旧消息保留、原文侧栏里能看到，但不再参与判断，也不再发给模型；只引用旧版本的证据会被跳过。Claude Code 靠同一个上级下挂着多条提问来认（最晚的是当前版本，旧提问到新提问之间的回复一起算旧版本）；粘贴和扩展导入靠再次导入时同一位置换了内容来认。Codex 和 VS Code 自带聊天的编辑格式没有见过真实样本，暂不处理。

只有 AI 提出的规划不进入范围，放在待确认的建议区。改正导入对话的发言者之后，所有证据按新的发言者重新判断。

## 模型

- `.env` 里的 `CORPUS_MODEL` 固定版本，每条证据都记下模型和提示词版本。
- `CORPUS_MODEL` 以 `claude-` 开头（如 `claude-sonnet-5-5`）时，用本机已登录的 Claude 订阅（`claude -p`，`src/extract/model.ts` 的 `claudeCli`）：只传少数环境变量（`ANTHROPIC_API_KEY` 不会传下去），关掉工具、MCP、自定义设置和会话记录，第一次调用前核对是订阅登录。命令行整理完会打印这次的用量。
- 其余值走 DeepSeek（兼容 OpenAI 的接口），要 `DEEPSEEK_API_KEY`。

## 按实际干活的地方归项目

会话的起点目录没绑定项目时（常见：从上层目录开、中途才进项目），只有 `sync --since` 才会读整份会话判断归属：看每一行的工作目录和工具参数里的绝对路径，某个项目（含它的 git worktree）占了一半以上就归这个项目。起点目录本身不算；没落在项目里的路径要磁盘上真有才算。没归上的会话列出标题，不读内容。`--since` 之前的消息不发给模型，直接算已整理，所以第一次接入不会回头整理全部历史。Codex 的子 agent 会话和 Claude Code 的一样不读。
