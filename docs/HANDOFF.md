## 2026-10-09：负责人模式收进 Crew

**来源：** 10-08 用户用 Claude Code 当负责人、派精简只读的 `codex exec` 做一次客户材料分析，一次跑通；10-09 要求收进 Crew，并按之前定的方向向 Orca 看齐。

**实测：** 真跑一次三张卡（两张并行，验收后第三张依赖它们），每张约 50 秒；第三张收到了前两份交付的路径；17 条出处全部对回原文；跑完没有残留进程。另外发现插件带的 MCP 不能单独关（会让 Codex 读配置报错退出），现在整体关插件，再逐个关配置文件里的 MCP，关完复查。

**同日再改：不再原地等，退回不从头重来。** 实测每个执行者启动就要约 3 万 token，所以：`run` 改成派出就返回，每张卡有自己的看守进程；新增 `wait`，交回一张通知一张；`reject` 后 `--retry` 用 `codex exec resume` 接着原会话改（实测多花约 4 千 token，从头重派约 2.8 万）。指南新增“什么活不值得派”。踩到两处：看守进程和回执写入有先后冲突，已改成先写回执；`resume` 不认 `-C`，不钉目录会落到启动命令所在目录，已钉死。

**同日：布局往返保留会话组合。** 以前四宫格选了 4 个会话，切到单窗再切回来，会被截断后用别的会话补满。现在每种布局（单窗／双栏／四宫格）各记一份显示的会话，往返不丢，刷新后也在；旧存档（只有一份 selected）会归给它当时的布局。改动在 `web/workspace.js`，新增 `tests/workspace-layout.test.ts`。**没在浏览器里看过实际切换**，只验过选择逻辑本身。

**后续已更新：** 看板的“负责人运行”已可只读查看这类运行，但不写入任务库；Codex 已支持声明 `可写：` 并用 `--write` 授权的写卡，Claude 仍只读。当前统一使用本仓库入口；窗口、分屏和项目标签的历史边界见下文。

## 环境和坑

- 运行：Node 22.18+，`npm run corpus -- help`。`.env` 放 `DEEPSEEK_API_KEY` 和 `CORPUS_MODEL`，不提交。
- 仓库是公开的：提交前 `git diff --cached | grep -iE "sk-|/[U]sers/|@gmail"` 自检，别把真实对话、个人路径、私人项目名写进文档。
- Claude Code 命令行也可以当模型，但要 `env -u ANTHROPIC_API_KEY`，见 `docs/contracts.md`。
- Node 直接跑 TypeScript，不支持构造函数参数属性、enum 这类要编译的语法（`erasableSyntaxOnly`）。
- 全局 git pre-commit 钩子：同一个提交里既改已有测试文件、又改源码会被拦。新增测试文件不受影响。要改旧测试就单独提交。
- 页面服务只监听 127.0.0.1；写操作必须带 `x-corpus: 1` 请求头。
- 第一次在页面上同步会弹出“发送说明”，同意后才调用模型；命令行 `extract` 直接整理，会打印一行说明。
