# Crew：本地 Agent 工作台

## 终端团队入口（2026-09-30）

功能优先的日常团队协作现在可以直接在终端使用 TUI，网页入口继续保留。在仓库目录运行：

```sh
npm run crew -- team --demo
npm run crew -- team "/你的项目目录"
```

第一条是离线演示，不调用模型；第二条默认 Codex 团队、只读检查，进入后输入目标开始。`--goal "目标"` 可立即开始，`--write` 修改隔离副本，`--mode delegation` 选择 Claude 负责人 / Codex 执行者。

Tab 切换成员，直接输入补充信息；F2 查看成果与变更。`/answer Q1` 回答提问，`/approve A1 y|n|c` 处理审批，`/interrupt` 请求中断，`/quit` 或 Ctrl+D 停止并退出。`/help` 查看所有操作。此入口创建自己的专用团队，不接管网页、Orca 或既有原生 CLI 会话；尚未打包为终端插件。

真实 PTY 已验证键盘、原生协议替身与离线交互，真实模型会话仍受本执行沙箱写入 Codex SQLite 状态的限制。使用、固定检查和边界见 [终端团队说明](../scripts/probes/team-tui/README.md)。后面的窗口体验是原有网页路线。

## 负责人模式：Claude Code 拆卡，Codex／Claude 执行者干活

Claude Code 把活拆成任务卡，并行派给 Codex 或 Claude 执行者，交回的结论要带 `/绝对路径:行号` 出处，负责人验收后依赖它的下一步才开跑。最适合要读一大堆材料、能拆成互不依赖的几块的只读分析；也能派写卡改文件，写卡须声明可写路径并由 `--write` 授权。

```sh
crew worker run <运行目录> --cwd <工作目录> --goal <目标>  # 就绪的卡开跑，派出就返回；写卡等 --write
crew worker wait <运行目录> --minutes 10                  # 新交回或新卡住即返回，附进度
crew worker check <运行目录>/t1.out                       # 核对交付里的 /绝对路径:行号 出处
crew worker accept <运行目录> t1 --note <说明>             # 验收；通过后自动派出本次解锁的下游
crew worker reject <运行目录> t1 --note <说明>             # 退回
crew worker run <运行目录> --retry t1 [--fresh]           # 默认接着原会话改；--fresh 明确重开
crew worker status <运行目录>                             # 逐卡进度
crew worker guide                                         # 完整规则，由命令自己打印
```

卡头、写卡、接续、`watch`／`pause`、跨运行依赖、`result-v1` 等完整规则由 `crew worker guide` 打印。这类运行不进任务库；看板的“负责人运行”可只读查看状态、进度、验收与结论。

## 本地管家与任务看板

`crew housekeeper` 或双击 `scripts/housekeeper/打开本地管家.command` 打开今日安排，`--dry-run` 只打印启动计划。数据沿用正式 Crew 数据目录；原生 helper、扫描器、钥匙库和外部任务来源通过环境变量或 `<Crew 数据目录>/housekeeper.json` 显式配置。今日页整理已有任务，安全页只展示凭证元数据和使用记录；外部任务库、钥匙库只读，不读取钥匙串中的秘密。未配置组件显示不可用，今日页仍可展示 Crew 本地任务。配置表、启动边界与假 Key 测试限制见 [本地管家说明](HOUSEKEEPER.md)。

任务看板的停止请求绑定原运行编号；重启后未结回执标为待重新核对，重新核对时 Crew 证实原运行已结束就自动结算，查不清的才由用户核对原编号、确认结束后结算，不能用同项目的新运行替代。`scripts/task-board/review.py` 归档隔离成果，`--accept` 只合并代码，不验收任务、不改任务库；冲突时拒绝整次合并，删除只报告。详见 [任务看板说明](../scripts/task-board/README.md)。这与下文终端进程、团队消息不能跨服务重启恢复的限制不同。

## 打开项目

在仓库目录运行（需要 Node 22.18+，首次先 `npm install`）：

```sh
npm run crew -- open "/你的项目目录"
```

也可用 `./bin/crew open "/你的项目目录"`。命令绑定项目目录、启动本机服务，并以 Chrome 应用模式打开独立窗口；找不到支持的浏览器时使用默认浏览器。`--no-open` 只启动服务，`--port 4191` 可指定端口。

macOS 启动器已生成在 `dist/Crew.app`，可以双击打开。重新生成用 `npm run mac-app`。这是依赖当前仓库和 Node 的启动器，尚不是自包含安装包；移动仓库后需要重新生成。

## 在窗口里工作

1. 选择已绑定的工作目录，点击“启动 Codex”或“启动 Claude”。机器上需要预先安装并登录相应 CLI。
2. 直接在终端输入任务。目录信任、文件修改和命令审批保留相应 CLI 的原生交互；Crew 不自动批准。
3. 用会话标签切换终端，选择“单窗”“双栏”或“四宫格”，最多同时查看四个会话。较窄窗口会改为上下排列。
4. 刷新页面或切到其他项目不会主动终止会话；重新进入会回放保留的输出。点击“停止进程”结束对应会话。

接入设置可以为已有项目绑定目录；“打开项目”可以添加项目。新终端只允许从该项目绑定的真实目录启动。

点击终端顶部“命名”，可以把会话命名为“页面开发”“接口联调”等；留空保存会恢复默认名称。顶部可以搜索会话名称、Agent 或目录，左侧可以搜索项目。搜索只筛选标签，不会停止或改变当前显示的终端。

布局、选中会话、工作目录、会话名称和最近项目保存在当前浏览器本地。刷新或切换项目后会恢复布局，从首页重新打开时回到最近项目。这些偏好不跨浏览器同步，也不代表服务重启后能恢复进程。

## 订阅和运行位置

当前入口检查 Codex 的付费 ChatGPT 登录与 Claude 的订阅登录，子进程排除 API Key 等环境变量，不做 API Key 回退。CLI 进程和项目文件在本机；模型推理仍由对应供应商提供。全局登录配置不由 Crew 修改。

Claude 以显式审批模式启动；Codex 使用 workspace-write 沙箱和 on-request 审批。两者的权限语义不同，仍以各自终端提示为准。为避免既有自动化配置取消审批，Claude 启动时不加载用户、项目和本地 settings 来源；这些 settings 中配置的插件、MCP 等也不会自动继承。
