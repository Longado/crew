# Crew UI v6 阅读连续性与状态反馈 Implementation Plan

> **For agentic workers:** When implementation is authorized, reuse the selected execution method; use superpowers:executing-plans for inline execution or superpowers:subagent-driven-development when delegation is applicable and authorized. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 更新时保留已展开的背景，连接及运行提示准确反映状态，并区分本次运行结束与任务验收完成。

**Architecture:** 沿用 v5 的任务列表、详情／运行双栏、A 浅色／C 深色和已有渲染缓存。改动集中于同一前端文件的渲染与提示分支，由一位实现 Agent 顺序完成，避免多人同时修改；既有执行、数据和任务状态接口保持。

**Tech Stack:** 原生 JavaScript、HTML/CSS；现有 Node DOM port 测试、TypeScript 类型检查；无新依赖。

## 讨论结果与边界

三位 Agent 分别检查信息呈现、交互连续性和状态来源，并交叉讨论后同意 A／B／C。以下是源码和 DOM port 证据；没有实际页面截图。

| 项 | 当前触发与问题 | 本轮决定 | 行为验收 |
|---|---|---|---|
| A 阅读连续性 | 同任务的文字或 busy 改变导致 inspector 重建，背景重新折叠 | 同一 inspectedId 保留当前展开态；换任务默认折叠 | 内容更新、busy 变化、详情／运行切换仍展开；换任务不串状态 |
| B 状态反馈 | 断连后筛选／点选调用 render，页脚伪造新同步；busy 结束旧提示残留 | 时间仅成功 refresh 更新；只清已解除的两条自有提示 | 本地操作不更新时间；断连保留上次成功时间；API 错误经失败／恢复仍保留 |
| C 运行语义 | completed 与任务完成共用文案，结果摘要在已结束折叠区内 | 运行独立用“运行结束／需处理”；已有 job.label 摘要外显一次 | 只读运行结束仍可对应 todo 任务；失败／待确认摘要与错误可见；已结束历史仍折叠 |

搜索计数与跨日日期后置。A 仅保证背景展开态，不承诺重建后的滚动位置。C 接受增加一段既有结果摘要的代价，不加解释段落、不截断摘要；已结束历史的成员／输出／回执沿用折叠，blocked 与 live 的控制沿用现有分支。等待中的 Crew 链接和停止操作保持可见。

本轮只修改 `web/task-board.js`、`tests/task-board-ui.test.ts` 及计划／预览／验证／交接记录。`web/task-board.html`、CSS、任务 DB、清单、依赖、后台、MCP／CLI 保持。只读默认、完整 goal、权限和目录可见、确认后派发保持。现有工作树有其他未提交工作，保留；本轮不自动提交、发布或运行模型。

- [x] **Step 2：最小实现 A。**

在已有渲染状态旁增加 `renderedTaskId = null`；在确定当前 inspectedId 后、更新 inspector 前读取展开态。使用以下顺序，避免手动展开触发额外缓存重绘；换任务默认 false，不增加跨任务记忆：

```js
const contextOpen = renderedTaskId === inspectedId && Boolean(document.querySelector('#inspector .task-context')?.open);
html('inspector', inspector(data.tasks.find(t=>t.task_id===inspectedId)));
const context = document.querySelector('#inspector .task-context');
if (context) context.open = contextOpen;
renderedTaskId = inspectedId;
```

- [x] **Step 3：最小实现 B。**

增加 `lastSyncedAt = ''` 和两条现有提示常量：

```js
const connectionNotice = '暂时无法连接任务看板，恢复后会继续同步。';
const busyNotice = '已有任务运行中，请在运行记录查看进度，结束后再启动。';
```

从 `render()` 删除同步时钟写入。`refresh()` 成功取得数据时更新时钟及页脚，按精确字符串清除自有提示；只清已解除的 busy，不清未知操作错误：

```js
lastSyncedAt = new Date().toLocaleTimeString('zh-CN', {hour:'2-digit', minute:'2-digit'});
$('synced').textContent = '已同步 · ' + lastSyncedAt;
const notice = $('notice').textContent;
if (notice === connectionNotice || (!isBusy() && notice === busyNotice)) $('notice').textContent = '';
```

失败分支保持连接样式更新，页脚保留上次成功时间；只替换空白或自有消息：

```js
$('synced').textContent = '连接中断 · ' + (lastSyncedAt ? '上次同步 ' + lastSyncedAt : '尚未同步');
if (['', connectionNotice, busyNotice].includes($('notice').textContent)) $('notice').textContent = connectionNotice;
```

busy 拦截仍立即返回，不派发；仅在 notice 为空或已是自身 busyNotice 时写 busyNotice。保留提交成功原有显式清提示。不要引入通知队列、类型模型或定时器。
