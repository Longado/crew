# Crew UI v7 搜索计数与运行日期迭代计划

**Goal:** 搜索列表与标签计数采用同一口径，跨日运行记录能够区分。

**Architecture:** 沿用 v6、A／C 配色与现有双栏。两位 Agent 分别核对交互和信息密度并互评，确定本轮只改前端显示派生值。一位实现 Agent 顺序修改共享文件，其后独立复核；不加依赖。

**Tech Stack:** 原生 JavaScript、现有 Node DOM port 测试、TypeScript 检查。

## 讨论结论与范围

1. 计数当前统计全库，而列表先搜索再分类，容易让空列表仍显示非零数字。先得到 `queryMatches`，四标签统计这个集合，再应用当前分类。各标签数量表示当前关键词在该分类下的匹配数，独立于正在选择的分类。保留精确任务／来源编号匹配、排序与选中规则。
2. 运行时间当前只显示 HH:mm，不同日同刻无法区分。统一显示数据原字符串的 MM-DD HH:mm；保留 `datetime` 原文，不做日期解析或时区转换，不新增“今天／昨天”逻辑。

计数不新增正文；日期每项多 6 个字符，沿用已有 meta 行。窄窗换行与视觉效果仍需实际窗口检查。年份增强、日期分组、排序分页、摘要截断和正文滚动位置恢复后置。

生产范围仅 `web/task-board.js` 与 `tests/task-board-ui.test.ts`。HTML／CSS、goal、只读默认、权限与目录、确认及派发 payload、后台／MCP／CLI、任务 DB 和清单保持。保留其他工作树改动，不自动提交、发布、派发或运行模型。
