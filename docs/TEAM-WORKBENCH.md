# Crew 团队工作台

## 终端方式（2026-09-30 最新）

运行 `npm run crew -- team [目录]`，在终端输入目标并管理成员；默认 Codex 团队与只读检查。提问、审批、中断和验收记录复用本文对应的团队逻辑，创建本次专用会话，不共享或接管已有网页团队。`--demo` 展示离线交互，`--write` 修改隔离副本；详细用法与真实运行待验证项见 [终端入口](../scripts/probes/team-tui/README.md)。网页继续使用下方的简洁入口。

## 简洁入口（2026-09-30 最新）

日常从终端工作台进入。需要独立委派时打开“团队”，填写目标并启动；默认 Codex 团队与只读检查，其他协作方式、目录和执行权限在“运行设置”中选择。成员状态留在底部一行 TEAM 条，点击成员处理补充信息、提问和中断；任务与连接详情按需展开，新的审批和 Claude 连接命令会展开相应区域。修改仍留在隔离副本。

本轮只简化当前前端；终端插件尚未实现。查看 [合成预览](verification/crew-compact-preview-2026-09-30.html) 与 [验证记录](verification/crew-compact-acceptance-2026-09-30.json)。真实模型闭环和视觉检查仍待通过。

## Codex 团队与底部成员条（2026-09-30）

团队页选择 **Codex 团队 · 原生子 Agent**，填写当前目标、绑定目录与权限，再启动。Codex 作为负责人创建原生成员；不需要启动 Claude。在运行设置选择“Claude 负责 / Codex 执行”仍使用原来的 Claude 负责人 / Codex 执行者。

当前项目页面底部的 **TEAM** 条展示成员活动及已验收任务数。点击成员可查看职责、记录、成果和差异；原生成员可接收补充信息，原生提问有独立回答入口，审批由你决定。请求中断后需等原生结束确认。执行者完成不自动增加验收进度，负责人读取实际成果并接受后才计入。

断线时显示最后观测并暂停操作；页面切换会重读服务快照，服务重启仍不恢复团队。读写任务在隔离副本中执行，不自动合并到源项目。

源码与无模型检查已落地，真实模型和视觉验收尚未通过。真实 App Server 启动在建立会话前断开，浏览器检查被 request-header policy 错误阻塞。接力见 [固定验收入口](../scripts/probes/codex-team/README.md)、[验证回执](verification/codex-team-acceptance-2026-09-30.json) 和 [合成预览](verification/codex-team-preview-2026-09-30.html)。

## 目标委派使用入口

1. 运行 `npm run crew -- open "/你的项目目录"`，进入项目的“团队”。在运行设置选择“Claude 负责 / Codex 执行”，选一个已绑定目录，填写本次目标与验收要求，选择“只读检查”或“修改隔离副本”。
2. 点击启动，按页面命令在本机交互终端连接 Claude，完成原生信任提示；如工具未就绪，补发 `Call corpus_bridge ready now.`。双方 ready 后目标才送给 Claude。
3. Claude 只读项目与本轮隔离成果，按需要派单。Codex 接单、提问、提交结构化成果；页面分别显示“待接单 / 执行中 / 待补充 / 待检查 / 负责人已接受”。负责人接受仍需用户核对最终交付。
4. 补充信息发送给 Claude；负责人回复 worker 时必须带 task_id 和 attempt。审批卡显示原生命令或变更，用户选择允许、拒绝或拒绝并中断。未支持的原生请求停止后续派发并显示原因。
5. 取消活动任务先显示“正在取消”，收到对应原生结束事件才显示“已取消”。取消、订阅故障或失联后不再自动派发；核对产物后停止并重启团队。待派发任务可单独取消。
6. 本次目标最多 3 项任务，每项最多 1 次返工，Codex 同时只处理一个任务。成果提交与负责人检查不能提前释放仍在执行的原生 turn。超过 10 分钟只提醒，不假定已停止。

修改模式复制源目录的当前文件，保留未提交与未跟踪内容，记录 SHA-256 基线。副本不含 `.git` 和 `node_modules`，不共享硬链接；遇到符号链接或不支持的文件类型明确停止复制。需要依赖的项目须另行处理检查环境，不会自动安装依赖。页面给出副本与基线路径，源项目不自动合并、提交或清理。

委派启动要求 Codex 使用 on-request 且由用户审批，关闭额外可写目录、默认临时目录写权限与网络；启动后核对 App Server 返回的实际权限，若不符合要求则停止。[配置依据](https://learn.chatgpt.com/docs/config-file/config-reference?translationFallback=zh-Hans)。文件名单用于职责和成果复核，不能代替目录沙箱；额外权限仍由用户处理原生审批。只读项目文件可由 shell 工具读取，联网、额外插件与递归 Agent 未随委派启用。

任务、审批和消息保留在当前服务内存中，刷新恢复快照，服务重启不恢复；隔离副本仍保留。当前 Team 创建专用会话，不接管日常 PTY 或 Orca 的已有会话。

## 本地使用

1. 在项目仓库运行 `npm run corpus -- serve`，打开命令输出的本地地址。
2. 选择已有项目，进入“团队工作台”，点击“启动团队”。同一服务同时运行一个项目的团队。
3. Codex 创建专用 App Server 会话。复制页面生成的 Claude 启动命令，在本机交互终端执行，确认该专用测试目录的原生信任与本地 Channel 开发提示。
4. 如果 Claude 首轮未加载工具，在该 Claude 会话输入 `Call corpus_bridge ready now.`。等两张工牌都显示可收消息后，选择成员发送。
5. 点击工牌查看该成员消息，点击双方连线查看跨成员交流。回复会展示所回复的原消息。
6. 点击“停止团队”结束本次专用连接；原来已打开的工作会话不受影响。

要求本机已安装可用的 Codex、Claude Code，并分别完成 ChatGPT 和 Claude 订阅登录。启动时核对认证类型并从子进程环境排除 API Key，不自动改走 API 计费。Claude Channels 仍采用本地开发接入方式。2026-09-29 实际验证的是 ChatGPT Pro 与 Claude Max，不代表所有订阅层级均已测试。

## 当前边界

- 固定两个成员；委派模式固定 Claude 负责人 / Codex 执行者，尚无更多成员、拖动布局或负责人互换。
- 新建专用会话；未接管任意已有终端。Codex 是 App Server thread，不是嵌入网页的可见终端。
- Bridge 持续随本地服务运行。刷新页面恢复当前快照；服务重启不保留消息，重新启动团队也会清空本次消息。
- Claude 首轮工具加载问题仍需人工补发 ready；不声称无人值守接入。
- “已传输”仅代表写入通信接口；收到有效回复才显示“已回复”。不会以动画猜测模型正在思考。
- Codex 的工具回复与其最终自然语言输出均保留，可能出现内容相近的两条页面消息。
- 停止只针对本次拥有的子进程与连接，不回滚已经产生的工作。显式停止通过本轮私有标记结束 Claude；意外失联允许约 60 秒恢复，避免页面同步引起的短时阻塞误杀会话。
- 在线静态演示不能启动本机团队。

实现沿用原生 JavaScript/CSS、Node/TypeScript 和项目本地服务。新增 `@modelcontextprotocol/sdk@1.31.0` 用于独立 Channel relay；原有只读 MCP 保持不变。
